# pssst V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver pssst's complete macOS-first local-first recording, transcription, correction, review, and settings experience with a runnable FastAPI/PostgreSQL service.

**Architecture:** Rust owns durable session files, audio tracks, capture backend lifecycle, and upload queue. FastAPI/PostgreSQL owns remote processing state and immutable transcript versions. React consumes typed facades and reflects independent recording, transcription, and correction states without entering the native critical path.

**Tech Stack:** Tauri 2/Rust, React/TypeScript/Vite, FastAPI/Python, PostgreSQL/SQLAlchemy/Alembic, faster-whisper, OpenRouter HTTPS API, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-07-pssst-first-vertical-slice-design.md` and `/Users/jyvor/.codex/attachments/8052b364-b4a5-4095-a6ca-25d624bbe835/pasted-text.txt`

## Global Constraints

- Recording is local-first and has no dependency on React, network, backend, Whisper, or OpenRouter.
- Application audio and microphone audio remain separate tracks.
- `CaptureBackend` is platform-agnostic; ScreenCaptureKit is only in the macOS adapter.
- PostgreSQL runs through Docker Compose; FastAPI/faster-whisper runs on the host.
- Raw Whisper text is immutable and separate from corrected/final text.
- Recording, transcription, and correction have independent states and retry handling.
- No Redis, Celery, Kafka, Electron, SwiftUI, or unrelated AI features.
- Preserve pssst's existing design language and first screen.
